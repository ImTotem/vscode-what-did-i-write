# What Did I Write?

내가 작성한 파일, 코드 줄, 커밋을 찾아보세요.

[English](README.en.md) | [한국어](README.ko.md)

지원 UI 언어는 English와 한국어입니다. 별도 설정 없이 VS Code의 표시 언어를 자동으로 따릅니다.

What Did I Write?는 현재 체크아웃한 Git 저장소에서 내가 작성한 코드를 찾아주는 데스크톱 VS Code 확장입니다. VS Code 시작이 끝나면 자동으로 동작하며, 로그인·기준 커밋 선택·클라우드 서비스·GitHub 연결이 필요하지 않습니다.

분석은 로컬 Git만 사용합니다. 전역 `user.name`과 `user.email`을 읽고 현재 `HEAD`에서 도달 가능한 커밋의 작성자와 비교합니다. 이름이나 이메일 중 하나만 일치해도 내 커밋으로 판단합니다. stage 여부와 관계없이 아직 커밋하지 않은 변경 및 추적되지 않은 파일은 내 현재 작업으로 처리합니다.

## 요구 사항과 설치

- 데스크톱 VS Code 1.96 이상. 웹 확장 호스트는 지원하지 않습니다.
- `PATH`에서 실행할 수 있는 로컬 `git`.
- 전역 Git 사용자 정보 `user.name` 또는 `user.email` 중 하나 이상.

로컬 설치 패키지를 만들고 설치합니다.

```powershell
npm install
npm run package
code --install-extension .\what-did-i-write-0.1.0.vsix
```

설치 후 Git 저장소를 여세요. Git 저장소가 아닌 폴더에는 아무 표시도 하지 않습니다. Git이나 전역 사용자 정보를 찾지 못하면 해결 방법이 포함된 경고를 한 번 보여주고, 자세한 내용은 **What Did I Write?** 출력 채널에 기록합니다.

## 화면에 표시되는 내용

기본 탐색기에서는 내 현재 코드가 들어 있는 파일만 꾸미고, 그 표시를 상위 폴더까지 전달합니다.

- `A` — 내가 추가한 현재 파일 또는 추적되지 않은 파일.
- `M` — 내 것으로 추적된 줄이나 stage/unstage 변경이 있는 파일.
- `◷` — 과거에는 내가 수정했지만 현재 파일에는 남아 있지 않은 경로. 현재 탐색기 배지 대신 **과거 활동**에 표시됩니다.

**MY CODE**는 탐색기 및 소스 제어와 나란히 있는 독립 Activity Bar 메뉴입니다. 다음 세 개의 뷰로 구성됩니다.

- **내 변경 사항** — 내 현재 파일을 실제 탐색기처럼 폴더 계층으로 표시합니다.
- **과거 활동** — 기본으로 접혀 있으며, 과거에 변경한 경로를 최신순으로 표시합니다.
- **파일 히스토리** — 선택한 파일 또는 줄의 현재 변경과 내 커밋을 표시합니다.

대상 텍스트 파일을 열면 내 작성 줄에 VS Code 네이티브 Quick Diff gutter 표시가 나타납니다. 소스 전체는 그대로 보이며 코드 위에 테두리를 그리지 않습니다.
What Did I Write?는 내 작성 줄을 뺀 가상 원본을 제공하고, VS Code가 `scm.diffDecorations` 설정에 따라 표시를 그립니다.
gutter 표시에 마우스를 올리면 막대가 넓어지고, 클릭하면 VS Code 네이티브 인라인 diff가 열립니다.
Git 내장 quick-diff 원본도 그대로 사용할 수 있습니다.
커밋 히스토리는 **파일 히스토리** 뷰 또는 줄 히스토리·파일 히스토리 명령에서 확인합니다.
바이너리 파일은 목록에 나올 수 있지만 줄 표시는 추가하지 않습니다.

히스토리 타임라인은 현재 작업 중인 변경을 가장 위에 두고, 그 아래 커밋을 최신에서 과거순으로 표시합니다. 방향이 적힌 세로 레일이 있어 시간을 일일이 읽지 않아도 순서를 알 수 있습니다. 항목을 클릭하면 원본 파일을 고정한 채 옆의 재사용 가능한 미리보기 diff가 해당 커밋 내용으로 바뀝니다.

## 기능 위치

| 위치 | 제공 기능 |
| --- | --- |
| Activity Bar → **MY CODE** | 내가 작성한 현재 및 과거 파일만 표시합니다. |
| **내 변경 사항** 제목 표시줄 | 새로 고침, 모두 접기, 내 코드 표시 숨기기/보이기. |
| **내 변경 사항** 우클릭 메뉴 | 탐색기 방식의 열기, 위치 표시, 경로 복사, 생성, 잘라내기/복사/붙여넣기, 이름 바꾸기, 삭제. |
| 편집기 네이티브 Quick Diff gutter / overview ruler | 내 작성 줄을 VS Code 네이티브 표시로 보여줍니다. |
| 편집기 gutter 호버 / 클릭 | 호버하면 막대가 넓어지고 클릭하면 네이티브 인라인 diff가 열립니다. 커밋 기록은 **파일 히스토리**에서 봅니다. |
| **파일 히스토리** | 최신순 커밋 레일. 항목을 클릭하면 원본 옆 미리보기 diff를 갱신합니다. |
| 명령 팔레트 | 다시 시도와 출력 보기를 포함한 모든 What Did I Write? 명령. |

## 명령과 설정

- `What Did I Write?: 새로 고침` — 발견한 모든 저장소와 뷰를 새로 고칩니다.
- `What Did I Write?: 모두 접기` — 현재 열려 있는 폴더를 전부 접습니다.
- `What Did I Write?: 내 코드 표시 숨기기` / `내 코드 표시 보이기` — 작업 영역의 시각 표시 상태를 저장합니다.
- `What Did I Write?: 다시 시도` — 전역 Git 설정을 바꾼 뒤 사용자 정보를 다시 읽습니다.
- `What Did I Write?: 출력 보기` — 진단 세부 정보를 엽니다.
- `What Did I Write?: 파일 히스토리 보기` — 활성 파일 또는 선택한 파일의 내 히스토리를 표시합니다.
- `What Did I Write?: 줄 히스토리 보기` — 현재 줄의 내 히스토리를 표시합니다.
- `What Did I Write?: 줄 배경 전환` — 선택 사항인 내 코드 줄 배경을 켜거나 끕니다.

현재 파일과 폴더 행은 실제 탐색기와 비슷한 우클릭 작업을 지원합니다. 내부 드래그 앤 드롭은 같은 저장소 안에서는 이동하고 저장소 사이에서는 복사합니다. 외부 파일 URI 드롭은 경로 포함 관계와 이름 충돌을 확인한 뒤 복사합니다. 과거 활동은 히스토리 및 경로 복사를 제외하고 읽기 전용입니다.

`myCode.visuals.enabled`의 기본값은 `true`입니다. 끄면 분석과 모든 뷰는 유지하면서 탐색기 색상과 네이티브 Quick Diff 표시를 숨깁니다. `myCode.editor.lineBackground`의 기본값은 `false`이며, Quick Diff 표시와 함께 은은한 줄 전체 배경이 필요할 때 켤 수 있습니다.

## 다중 루트 작업 영역과 새로 고침

각 작업 영역 폴더는 독립적으로 확인합니다. 같은 Git worktree를 가리키는 폴더는 분석 모델 하나를 공유하며, Git 저장소가 아닌 폴더에는 What Did I Write? 상태가 없습니다.

저장·생성·삭제·이름 변경·작업 영역 폴더 변경·보이는 편집기 변경과 VS Code에 포커스가 있을 때의 저장소 fingerprint 변경에 반응합니다. 새로 고침, checkout, commit, rebase가 발생하면 관련 인덱스를 다시 만듭니다. 전역 `user.name` 또는 `user.email`을 바꾼 뒤에는 **다시 시도** 또는 **새로 고침**을 실행해 사용자 정보를 다시 읽으세요.

일치하는 도달 가능 경로를 먼저 분석하고, 활성 편집기와 탐색기 요청을 백그라운드 작업보다 우선합니다. 저장소당 Git 하위 프로세스는 최대 네 개이며, 영구 캐시에는 메타데이터와 경로만 저장하고 소스 내용은 저장하지 않습니다.

## 개인정보 보호와 로컬 전용 동작

What Did I Write?는 GitHub나 원격 API를 호출하지 않고, 계정을 요구하지 않으며, 저장소 데이터를 업로드하지 않습니다. Git은 인수 배열로 로컬에서 실행되므로 경로나 사용자 정보를 셸 명령 문자열에 삽입하지 않습니다.

## 문제 해결

| 증상 | 해결 방법 |
| --- | --- |
| `What Did I Write?: Git 사용자 정보` 표시 | `git config --global user.name` 또는 `git config --global user.email` 중 하나 이상을 설정한 뒤 **다시 시도**를 실행하세요. |
| Git 경고 또는 결과 없음 | VS Code 환경에서 `git --version`이 동작하는지 확인하고 **출력 보기**를 여세요. |
| 파일이 보이지 않음 | 현재 `HEAD`에서 도달 가능하고 설정된 사용자 정보로 작성한 파일인지 확인하세요. 브랜치나 히스토리를 바꾼 뒤에는 새로 고치세요. |
| 줄 표시가 없음 | 내 히스토리 후보인 현재 텍스트 파일을 여세요. 바이너리 파일에는 의도적으로 줄 표시를 추가하지 않습니다. |
| `git log`보다 커밋이 적음 | 현재 `HEAD`에서 도달 가능하고 작성자가 일치하는 커밋만 보여주는 것이 정상입니다. |
| UI 언어가 예상과 다름 | VS Code 표시 언어를 바꾸고 창을 다시 로드하세요. 영어와 한국어가 포함되어 있습니다. |

## 개발과 검증

```powershell
npm install
npm run check
npm run test:run
npm run build
npx @vscode/vsce ls
npm run package
npm run test:extension-host
```

수동 검수는 VS Code에서 이 확장 프로젝트를 연 뒤 `F5`를 눌러 **Extension Development Host**를 시작합니다. 작성자가 두 명 이상인 Git 저장소를 열고 전역 Git 사용자 정보가 그중 한 명과 일치하는지 확인한 다음 아래를 검증합니다.

1. **내 변경 사항**에 내 현재 파일만 접을 수 있는 폴더 트리로 표시됩니다.
2. **과거 활동**은 최신순이며 읽기 전용입니다.
3. 네이티브 Quick Diff gutter와 overview ruler 표시가 코드를 가리지 않습니다.
4. gutter 표시는 호버하면 넓어지고 클릭하면 VS Code 네이티브 인라인 diff가 열립니다.
5. 타임라인 커밋을 클릭하면 원본은 열린 채로 옆에 해당 커밋의 diff가 표시됩니다.
6. 내 코드 표시 숨기기를 누르면 뷰와 분석은 유지하면서 탐색기 및 편집기 표시만 사라집니다.
7. VS Code 표시 언어를 영어와 한국어로 바꾸고 다시 로드하면 확장 UI 전체가 해당 언어로 바뀝니다.
